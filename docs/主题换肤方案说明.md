# antd + element 运行时换肤方案说明

> 需求：用户在页面上手动选主题色，antd 全套组件 + element-ui 全套组件 + 自定义样式（顶部导航、面包屑等）整套联动。
>
> **当前状态：引擎已启用**。构建侧配置在 `src/theme/themeColorReplacer.js`（由 `vue.config.js` 实例化），
> 运行侧在 `src/theme/ThemeManager.js`（`changeColor` 调用），案例页 `/theme`（`ThemeDemo.vue`）
> 覆盖两套 UI 的组件案例，并带「级联自检」工具（`src/theme/themeAudit.js`）辅助排查规则误伤。

一句话概括：**antd 的颜色在构建期就写死进 CSS 了，运行时改不了 less 变量，于是退而求其次——在运行时对"最终产出的 CSS"做颜色的字符串替换。**

---

## 一、为什么 antd-vue 1.7.8 换色难

antd v1 是 antd 3 血统，主题色靠 less 变量 `@primary-color`。但 less 是**编译期**语言：

```less
.ant-btn-primary { background: @primary-color; }
.ant-btn-primary:hover { background: ~`colorPalette('@{primary-color}', 5)`; }
.ant-btn:focus { box-shadow: 0 0 0 2px fade(@primary-color, 20%); }
```

`fade()` / `darken()` / `colorPalette()` 这些函数**必须拿到真实颜色值才能算**。`less-loader` 编译完，产出的 CSS 已经是死值：

```css
.ant-btn-primary { background: #1890ff; }
.ant-btn-primary:hover { background: #40a9ff; }
.ant-btn:focus { box-shadow: 0 0 0 2px rgba(24,144,255,.2); }
```

浏览器里 `@primary-color` 早就不存在了，全是纯字符串。想运行时全套换色，只有三条路：


| 路                       | 做法                                                | 代价             |
| ------------------------ | --------------------------------------------------- | ---------------- |
| 重新编译 less            | 浏览器里跑 less.js + antd 源码，`modifyVars` 重编译 | 慢、闪烁、体积大 |
| 预编译多套               | 每套主题编译一份完整 antd css                       | 体积 ×N         |
| **运行时替换（本方案）** | 对已产出的 CSS 做**颜色字符串替换**                 | 只需存几组色值   |

---

## 二、运行时替换的核心洞察

**一套主题和另一套主题的 CSS，结构完全一样，只有颜色值不同：**

```css
/* 蓝主题 */ .ant-btn-primary { background: #1890ff; }
/* 绿主题 */ .ant-btn-primary { background: #52c41a; }
```

既然只有颜色变了，就不需要重新编译——**把 CSS 文本里所有 `#1890ff` 换成 `#52c41a`，把所有派生色换成对应派生色**，就等于换了主题。这就是 `webpack-theme-color-replacer` 的全部思想。

唯一难点：**"派生色"也要一起换**。`#40a9ff`（hover 亮蓝）、`rgba(24,144,255,.2)`（focus 阴影）都是从 `#1890ff` 算出来的，换绿色时得换成绿色**对应算法**算出来的那一档。这就是"色阶（color series）"要解决的问题。

## 三、构建期发生了什么（`vue.config.js` → `src/theme/themeColorReplacer.js`）

`vue.config.js` 只按当前方案主色实例化插件，具体配置（含收窄/补丁）抽到了 `src/theme/themeColorReplacer.js`，
免得构建配置被大段换肤逻辑淹没：

```js
// vue.config.js
const createThemeColorReplacer = require('./src/theme/themeColorReplacer')
// ...
configureWebpack: {
  plugins: [ createThemeColorReplacer(theme.modifyVars['@primary-color']) ]
}
```

```js
// src/theme/themeColorReplacer.js —— 工厂，返回配好的插件实例
module.exports = function createThemeColorReplacer(primaryColor) {
  return new ThemeColorReplacer({
    fileName: 'static/css/theme-colors.css',      // 去掉 [contenthash]，见"方案边界"第 4 条
    matchColors: getThemeSerials(primaryColor),   // 基准色序列，与运行时 newColors 一一对应
    changeSelector(selector, util) { /* antd/element 宽泛规则收窄，见"方案边界"第 6 条 */ },
    resolveCss(css) { /* 补回被抽取丢掉的非主题色修正声明，见"方案边界"第 6 条 */ },
    injectCss: true,                              // 抽取结果注入 js，运行时无需下载 css
    isJsUgly: process.env.NODE_ENV !== 'development'
  })
}
```

`getThemeSerials(基准色)`（见 `src/theme/colorSeries.js`）= antd 序列 + element 序列的合并数组：

```js
function getAntdSerials(color) {
  const lightens  = 9 档 lighten 变体   // 由浅到深，覆盖 hover/active/border/faded
  const palettes  = generate(color)     // antd 官方调色板 primary-1 ~ primary-10
  const rgb       = '245,34,45'         // 逗号形式，给 rgba() 用
  return [...lightens, ...palettes, rgb] // 约 20 个"和主色相关的颜色"
}

function getElementSerials(color) {
  const lights = 9 档 mix(白, 主色, 10%~90%)  // $--color-primary-light-1~9：hover 背景/选中行/plain 按钮
  return [...lights,
    mix(黑, 主色, 10%),   // 按钮 :active（$--button-active-shade-percent）
    mix(主色, 黑, 97%)    // slider 滑块 hover（$--slider-button-hover-color）
  ]
}

function getThemeSerials(color) {
  return getAntdSerials(color).concat(getElementSerials(color))
}
```

element 的派生色在 theme-chalk 源码里全部由 scss `mix()` 算出（见其 `common/var.scss`、`button.scss`），
`varyColor.mix` 与 dart-sass 的 `mix()` 同公式同舍入——已用 sass 1.32.13 实测各方案主色，输出**逐字节一致**。
两序列有重复值（主色本身、部分档位撞值），新旧映射一致，重复无害。

插件拿这 ~30 个颜色**扫描 webpack 打包出的所有 CSS**（antd 的 less 产物和 element 的 scss 产物都在内），把**任何一条出现过这些颜色的规则整条抽出来**，汇成独立的 `theme-colors.css`。

也就是 `theme-colors.css` = "全站所有和主题色沾边的样式规则"合集。`injectCss: true` 让这份内容注入进 js，运行时无需再单独下载。

> 构建日志里的 `Extracted theme color css content length: ...` 就是这一步。

## 四、运行时发生了什么（`ThemeManager.changePrimary` → 库的 `changeColor`）

用户在 ThemePicker 里选绿色 `#52c41a`，`ThemeManager.changePrimary('#52c41a')` 里：

```js
await client.changer.changeColor({ newColors: getThemeSerials(color) }, Promise)
```

这里**又调一次 `getThemeSerials`**，但传的是用户选的新色：

```
matchColors (构建期,基准色) =  [#f5222d, #f7413f, ..., '245,34,45']
newColors   (运行时,新色)   =  [#52c41a, #73d13d, ..., '82,196,26']
                                 ↑ 下标一一对应 ↑
```

库做的事很直白：

1. 拿到那份 `theme-colors.css` 文本（已注入，无需下载）；
2. 把每个 `matchColors[i]` 用**字符串替换**成 `newColors[i]`；
3. 替换结果塞进 `<style>` 标签，`append` 到 `<body>` 末尾。

因为它在 `<body>` 尾部、优先级最高，就**覆盖**掉原来的规则。整套 antd + element（按钮、分页、开关、日期选择器…凡是用主色的）瞬间变色。再选一次再替换一次。**没有重编译、没有网络请求、没有闪烁**。

> 两边必须用**同一个 `getThemeSerials`**：函数一样、只是主色不同，产出数组的长度和顺序天然一一对应，下标 `i` 永远对得上。

## 五、两层架构：各管一摊

替换引擎只解决"UI 库自带组件"（antd + element）。你自己写的顶部导航背景、面包屑颜色它管不着。所以换色时两层并行：

- **第 ① 层（antd + element 组件）**：字符串替换引擎，业务不用管。
- **第 ② 层（你写的样式）**：全写成 `var(--primary-color)` / `var(--header-bg)`，往 `<html>` `setProperty` 一改全部联动。**零编译、零依赖**，最轻。

```js
async changePrimary(color) {
  // ① antd + element 全套组件 —— 走色值替换
  await client.changer.changeColor({ newColors: getThemeSerials(color) }, Promise)
  // ② 你自己的业务样式 —— 走 CSS 变量
  document.documentElement.style.setProperty('--primary-color', color)
}
```

## 六、完整数据流

```
构建期:
  presets.getPreset(VUE_APP_THEME) → 方案主色
        └─→ colorSeries.getThemeSerials(方案主色)   // antd 色板 + element mix 派生色
              └─→ ThemeColorReplacer 扫描所有 CSS（antd less 产物 + element scss 产物）
                    └─→ 抽出 theme-colors.css（含主色的所有规则）注入 js

运行期（用户在 ThemePicker 选色）:
  ThemePicker.pick('#52c41a')
        └─→ ThemeManager.changePrimary('#52c41a')
              ├─① changeColor(getThemeSerials('#52c41a'))
              │      └─→ 字符串替换 → <body> 追加 <style> → antd + element 整套变色
              └─② setProperty('--primary-color', '#52c41a') → 自定义元素联动
        └─→ localStorage 记住选择（刷新后 ThemeManager.init() 恢复）
```

## 七、方案边界（务必知道）

1. **只换"颜色"**。字号、圆角、间距等非颜色定制，替换引擎管不了（那些走编译期 `presets.js` 的 `baseVars`）。
2. **依赖"基准色能被匹配到"**。`matchColors` 的基准色必须等于编译期实际生效的 `@primary-color`——现在两者都取自 `getPreset()`，自动对齐，无需人工同步。
3. **色阶覆盖度**。极少数用非常规派生色的组件可能有个别色没覆盖到。真遇到，给 `getAntdSerials` / `getElementSerials` 补一档，或用插件 `resolveCss` 兜底。
4. **Node 17+ / OpenSSL3 的坑已绕过**：`fileName` 去掉了 `[contenthash]`，避免插件内部 md4 在 OpenSSL3（Node 17 起默认）下报错（`injectCss` 下文件名不重要，js 自带 hash）。
5. **生产构建需验证一次**。cssnano 的 colormin 理论上可能把个别颜色改写成短格式/命名色导致匹配不到（antd 那套没踩到，element 的 mix 值一般也压不短），改动后跑一次 `npm run build` 验证换色。
6. **宽泛规则会盖掉「非主题色的修正声明」——靠 `changeSelector` 收窄 + `resolveCss` 补回（均已实测踩坑）**。
   抽取器是按**声明**级别抽取的：一条规则里只有含主题色的声明会进 `theme-colors.css`，`color:#fff` / `border-color:transparent` 这类不含主题色的声明会被丢弃。原样式里这些修正常靠「文档顺序后来居上」压过主色打底；抽取后它们丢失、主色规则被追加到 `<body>` 尾又反超，于是白字/白图标/透明边框被主色盖掉——症状是换色后悬浮/深色底上文字变主色、和背景融为一体，或链接按钮冒出边框、步骤数字同色底看不见。

   **(a) `changeSelector` 收窄宽泛选择器**（`src/theme/themeColorReplacer.js`）：
   - **element 标签**：官方 `forElementUI.changeSelector` 只排除 `.el-tag--dark`；再补排除 `.el-tag--plain`（追加的 light-9 背景会盖 plain 白底）、四种功能色 `type`（其规则不含主题色不被抽取，但 `:not` 收窄会抬高优先级反盖功能色），关闭图标 `.el-tag__close` 同理。
   - **element 按钮**：落单的 `.el-button.is-active`（官方名单按 dist 合并写法匹配，sass 自编译时规则是拆开的会漏网）排除五种 `type`，护住 is-active 白字。**教训：官方名单对着 dist CSS 写，自编译规则拆分不同，要对着自己的编译产物核一遍。**
   - **antd 按钮**：默认按钮宽泛规则 `.ant-btn:hover,.ant-btn:focus`（色板 5 档）与 `.ant-btn:active,.ant-btn.active`（7 档）排除 primary/danger（护白字）和 link（否则悬浮冒边框）。
   - **antd 深色菜单**：`.ant-menu-horizontal > .ant-menu-item:hover` 等把 hover/选中文字染主色，本给浅色菜单用；但深色顶栏 `.ant-menu-dark` 同挂一个 `<ul>`、**同优先级**也命中，会把 hover 白字变主色。给 `.ant-menu-horizontal` 收窄成 `:not(.ant-menu-dark)`。（注：inline/竖向深色菜单的 `.ant-menu-item:hover` 只有 2 类权重，天然输给 `.ant-menu-dark …:hover` 的 3 类，**不受影响、无需收窄**——已实测。）

   **(b) `resolveCss` 补回丢失的修正声明**：在抽取产物末尾无条件追加两条——
   - `.ant-btn-link:hover/:focus/:active { border-color: transparent }`（原样式用 transparent 盖掉色板 5 边框，抽取后丢失 → 链接按钮悬浮冒边框）；
   - `.ant-steps-item-process .ant-steps-item-icon>.ant-steps-icon { color:#fff }`（进行中步的圈内数字白字，原样式盖掉主色打底，抽取后丢失 → 蓝底蓝字看不见）。

   **(c) 自检工具 `src/theme/themeAudit.js`**：`/theme` 页「级联自检」按钮。对追加样式表里每条声明，用真实 DOM 找证人元素、在原始样式表做「迷你级联仿真」选出原本的赢家，若追加规则能压过它且赢家不属主题色系即上报。覆盖 `color` / `background-color` / `border-*-color` / `box-shadow` / `text-shadow` / `fill` / `stroke`（忽略透明度比对，避免把 `rgba(主色,α)` 焦点环误报）。**局限：命中范围 = 当前 `/theme` 页出现的组件与状态，未上页的组件查不到。**
7. **功能色不能与任何方案主色的替换序列撞值（已实测踩坑）**。替换按"颜色字符串"匹配、分不清语义：功能色若用 antd 默认（`@error`/`@highlight`=@red-6 #f5222d、`@info`=@blue-6 #1890ff 等），其字符串或派生色会与主色序列相同，换主色时危险按钮、错误提示等会被**一并劫持变色**（尤其本项目两方案主色皆为红系，与默认红功能色仅一线之隔，实测极易撞）。
   而且**不只主色本身**：功能色的全部派生色（element 的 mix 浅色阶、antd 的 colorPalette 十档）都不能落进任何方案主色的 `getThemeSerials` 序列，否则同样被劫持。`±1` 微调**不够**（色板对微小输入不敏感、派生档照样撞）。
   修复：`presets.js` 的 baseVars 用**程序化搜出的「全派生零碰撞」近似色**——`@success #52b51b`、`@error`/`@highlight #f5132c`、`@info #1881fe`（`@warning #faad14` 无碰撞、保留 antd 默认），目视几乎无差。
   由单测 `src/theme/__tests__/preset-collision.spec.js` 兜底：**改功能色或新增主题方案后跑 `npm test`**，会校验每个方案主色序列与功能色派生色零碰撞。
8. **`@processing-color` 默认跟随主色**。antd 的「进行中」色（progress 进度条、steps 当前步、badge processing）默认是固定蓝、不随 `@primary-color`。`getPreset()` 里若方案没显式配置，则令其默认取主色，编译期与运行时换肤才能一起变（方案显式配了则以配置为准）。
9. **浅主色对比度风险**。白色文字/图标（主按钮文字、dark 标签、步骤数字…）是"钉死"的，主色一旦偏浅就会糊在主色底上——这是 antd/element 对浅主色的通病，取色器又允许任意色。`ThemePicker` 选色后按 WCAG 算白字对比度，`< 2.0` 时 `$message.warning` 提醒（两个预设均 >2 通过）。

## 九、维护指引

- **加主题方案**：在 `presets.js` 的 `presets` 里加一个对象（主色 + cssVars）。主色务必避开功能色序列，加完跑 `npm test`（第 7 条的碰撞单测会校验）。
- **改功能色**：改 `presets.js` 的 baseVars，同样跑 `npm test`。
- **选默认方案**：改 `.env` 的 `VUE_APP_THEME`（default / deepRed），重启 serve 或重新 build。
- **改了 `vue.config.js` / `themeColorReplacer.js`**：必须**重启 dev server**（构建期抽取只在启动时跑一次）；只改组件/样式则 HMR 即可。
- **换色后有组件没变、或白字被盖**：进 `/theme` 点「级联自检」，明细见控制台 `console.table`；未上页的组件先加进 `ThemeDemo.vue` 再自检。确属缺色阶就给 `getAntdSerials` / `getElementSerials` 补一档、或用 `resolveCss` 兜底修正声明。
- **升级 element-ui / sass**：`getElementSerials` 与 element 编译产物是逐字节对齐的，`mix()` 舍入一旦漂移，部分 element 色会**悄悄换不动且无报错**——升级后进 `/theme` 逐一核对 element 组件换色。
- **生产构建验证**：改动后跑一次 `npm run build`（见"方案边界"第 5 条 cssnano 注意事项）。
- **如需临时关闭引擎**：注释 `vue.config.js` 里 `plugins` 的 `createThemeColorReplacer(...)`，并把 `ThemeManager._apply` / `_applyPrimary` 里的 `changeColor` 调用注释掉（第 ② 层 CSS 变量仍会联动自定义元素）。

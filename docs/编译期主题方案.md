# 编译期主题方案（modifyVars 多方案改造）

> 2026-07-03。背景：antd 运行时换肤已暂时屏蔽（见《主题换肤方案说明》），
> 当前换肤只剩两层：**编译期 antd 变量定制（本文）** + **运行时自定义 CSS 变量（ThemePicker）**。

## 解决什么问题

以前 `vue.config.js` 里 `modifyVars` 直接写死 `{'@primary-color': '#f5222d'}`，有两个痛点：

1. 要定制的 antd 变量越来越多，堆在构建配置里难维护；
2. 想准备多套配色方案（不同环境/客户/品牌）时没有组织方式；
3. antd 的 `@primary-color` 和业务自定义的 `--primary-color` 分散两处，改色要人工对齐（老方案就栽过"三处对齐"的坑）。

## 方案结构

**唯一源头：`src/theme/presets.js`**（CommonJS，构建侧和浏览器侧共用）

```
baseVars   所有方案共用的 antd 变量（功能色、文字、边框、圆角、布局……）
presets    多套方案，每套 = { name, modifyVars(antd 差异变量), cssVars(业务自定义变量) }
getPreset(key)  返回合并后的完整方案；key 不存在回退 default；
                cssVars 里 --primary-color 自动取 @primary-color，天然对齐
```

**消费方两处：**


| 消费方                      | 取什么                                            | 作用                            |
| --------------------------- | ------------------------------------------------- | ------------------------------- |
| `vue.config.js`             | `getPreset(process.env.VUE_APP_THEME).modifyVars` | 编译期覆盖 antd less 变量       |
| `src/theme/ThemeManager.js` | 同一方案的`@primary-color` + `cssVars`            | 运行时写入自定义 CSS 变量默认值 |

`VUE_APP_THEME` 带 `VUE_APP_` 前缀，vue-cli 会把它内联进浏览器包，所以两侧读到的是同一个值、同一套方案。

## 日常操作

- **切方案**：改 `.env` 里的 `VUE_APP_THEME`（当前可选 `default` / `ocean` / `forest`），重启 serve 或重新 build。
- **加方案**：在 `presets.js` 的 `presets` 里加一个对象即可，其他文件都不用动。`modifyVars` 只写该方案的差异变量（一般就是 `@primary-color`、`@link-color`），公共部分自动继承 `baseVars`。
- **加公共默认变量**：往 `baseVars` 里加。antd v1 全部可覆盖变量清单见 `node_modules/ant-design-vue/lib/style/themes/default.less`。
- **加业务自定义变量**：往方案的 `cssVars` 里加（如 `--sidebar-bg`），ThemeManager 的 `init()` 会统一写到 `<html>` 上，业务样式用 `var(--xxx, 回退值)` 消费。

## 按主题区分样式（主题标记类）

`ThemeManager.init()` 会把当前方案 key 以 `theme-<key>` 类名打到 `<html>` 上
（如 `theme-default` / `theme-ocean`），供"变量表达不了的差异"使用——典型场景是**各主题配不同图片**：

```less
/* 默认主题的横幅图 */
.login-banner {
  background-image: url('~@/assets/banner-default.png');
}
/* ocean 主题换一张 */
html.theme-ocean .login-banner {
  background-image: url('~@/assets/banner-ocean.png');
}
```

- 选择器以 `html.theme-xxx` 开头即可，优先级天然高于不带前缀的默认规则；
- `<img>` 标签的 src 换图走不了 CSS，组件里用 `ThemeManager.getKey()` 拿方案 key（'default' / 'ocean'…）判断，或改成背景图写法；
- 若差异只是"一个值"（颜色、一张图的 URL），优先用 cssVars 表达（如 `'--login-banner': "url(/img/ocean.png)"`，
  样式里 `background-image: var(--login-banner)`），比铺 `html.theme-xxx` 规则更省；标记类留给"整块结构性差异"。

## 运行时切换与用户偏好存储（预埋结构）

为将来"放开动态换肤 / 用户主题存库"预留了两块结构，现在即可用（antd 部分除外）：

**① `ThemeManager.usePreset(key)`** —— 运行时切换整套方案：换 `theme-<key>` 标记类、全量写入该方案
cssVars、持久化选择（并重置用户自定义主色）。当前 antd 组件不跟随（引擎屏蔽中），恢复引擎后即为完整换肤。
`VUE_APP_THEME` 从此只扮演"出厂默认值/构建基准"，与运行时切换不冲突。

**② 存储层 `src/theme/themeStorage.js`** —— ThemeManager 的持久化只依赖 `{ load, save }` 两个方法，
默认实现是 localStorage。将来按用户存库时写一个接口实现替换掉即可，其余代码不动：

最简接法（能接受接口返回前短暂显示默认主题）：

```js
// 登录拿到用户信息后：
ThemeManager.setStorage({
  async load() {
    const r = await api.getUserTheme()            // ← 你的接口
    return { key: r.themeKey, primary: r.customPrimary }
  },
  async save(patch) {
    await api.saveUserTheme(patch)                // patch = { key } 或 { primary } 或两者
  }
})
await ThemeManager.init()   // 用新存储重新初始化（覆盖启动时的默认主题）
```

### 防闪变案例（本地缓存打底 + 接口校正）

上面的写法里，`init()` 要等接口返回才能换上用户主题，之前页面按编译期默认方案渲染——用户会看到
主题"闪"一下。解法是经典的 stale-while-revalidate：**localStorage 存一份"上次已知主题"快照，
启动时先用快照瞬间恢复（毫秒级、感知不到），接口回来发现不一致再校正**。

```js
// src/theme/apiThemeStorage.js —— 带本地缓存打底的接口存储
const CACHE_KEY = 'app-theme-cache' // 上次已知主题快照：{ key, primary }

function readCache() {
  try { return JSON.parse(localStorage.getItem(CACHE_KEY)) || {} } catch (e) { return {} }
}
function writeCache(patch) {
  try {
    localStorage.setItem(CACHE_KEY, JSON.stringify(Object.assign(readCache(), patch)))
  } catch (e) { /* 隐私模式忽略 */ }
}

export default {
  // load 只读缓存，同步级速度返回 → init() 不用等网络，首屏就是上次的主题
  async load() {
    return readCache()
  },
  // save 双写：接口 + 缓存（写穿），保证下次启动缓存就是最新的
  async save(patch) {
    writeCache(patch)
    await api.saveUserTheme(patch)
  }
}
```

```js
// 登录流程里（如 main.js 或路由守卫）：
import ThemeManager from '@/theme/ThemeManager'
import apiThemeStorage from '@/theme/apiThemeStorage'

ThemeManager.setStorage(apiThemeStorage)
await ThemeManager.init()               // ① 缓存瞬间恢复，无闪变

api.getUserTheme().then(r => {          // ② 后台拉真实数据，异步校正
  if (r.themeKey && r.themeKey !== ThemeManager.getKey()) {
    ThemeManager.usePreset(r.themeKey)  //    换库里的方案（save 会写穿刷新缓存）
  }
  if (r.customPrimary && r.customPrimary !== ThemeManager.getPrimary()) {
    ThemeManager.changePrimary(r.customPrimary)
  }
})
```

几个要点：

- **校正放在 `init()` 之后异步做**，不阻塞首屏；绝大多数情况下缓存和库一致，②什么都不改，用户全程无感。
  只有"用户在别的设备上改过主题"这种情况才会看到一次校正切换——这是语义正确的切换，不是闪变；
- **`save` 写穿**（先缓存后接口），所以正常使用路径下缓存永远和库同步，不需要额外的失效策略；
- 首次访问（无缓存）`load()` 返回空对象，页面保持编译期默认方案，接口回来后按库里的值校正——
  和"最简接法"表现一致，不会更差；
- 退出登录时记得 `localStorage.removeItem('app-theme-cache')`，避免下个账号短暂看到上个账号的主题。

## 注意事项

- antd 的 `@` 变量是**编译期**定制，运行时（`usePreset` / ThemePicker 选色）只影响标记类和 `cssVars`
  驱动的自定义元素；恢复替换引擎后 antd 颜色才会跟随运行时切换（非颜色变量永远编译期定死）。
- `.env` 改动 **必须重启 dev server** 才生效（webpack 只在启动时读一次）。
- 若日后恢复 antd 运行时换肤（webpack-theme-color-replacer），vue.config.js 注释块里的 `matchColors` 已改为 `getAntdSerials(theme.modifyVars['@primary-color'])`，直接放开即可，与当前方案自动对齐，无需再手工同步主色。
